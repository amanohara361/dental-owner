# 毎週木曜13時 — 立地情報の収集

`CLAUDE.md` の役割定義に従って実行する。
**毎週1エリアずつ**、対象を替えながら掘る。

## 手順

1. `docs/location-rotation.md` を開き、キューの**上から最初の `[ ]` のエリア**を
   今回の対象とする。
2. `reports/location/` の直近3ファイルを読み、調査の型と「未確認」項目を把握する。
   エリアは違っても**同じ切り口で埋める**（比較できるようにするため）。
3. 対象エリアについて、`docs/location-rotation.md` の
   「各回で必ず押さえる項目」1〜6を調べる（WebSearch / WebFetch を使う）。
   - 人口動態（推移・将来推計・世帯数・高齢化率）
   - 競合（歯科診療所数、人口10万対の密度、駅別の集積）
   - 診療圏（500m / 1km 圏の人口、線路・河川・幹線道路による分断）
   - 賃料（駅前 / 住宅地 / ロードサイドの坪単価、保証金の月数、居抜き）
   - 将来要因（再開発、新駅、住宅供給、乗降客数）
   - エリア固有の論点（屋外広告物条例、医療モール、自治体の助成）
4. `reports/location/YYYY-MM-DD.md` に書き出す（形式は `CLAUDE.md` の「レポートの形式」）。
   **冒頭に対象エリア名を明記する。**
5. `docs/location-rotation.md` の当該行を `[x]` に変え、実施日とレポートのパスを書く。
6. コミットして `claude/dental-startup-advisor-ctrpar` に push する。
7. チャットへの報告は100字以下。対象エリア名＋サマリ1行＋次のステップ1つ。

## 注意

- 「この立地なら成功する」「このエリアが有利」と断言・順位づけしない。
  条件と前提を書くところまで。
- 物件情報に相談者が特定できる情報を混ぜない。
- 賃料・人口データは調査時点を必ず記載する。
- 一次情報のページを直接開けない場合があるため、数値は原則
  「未確認・二次情報」として扱う（`docs/runbook.md` 参照）。
- 3〜4エリア溜まったら `reports/location/_comparison.md` に横断比較表を作る。
