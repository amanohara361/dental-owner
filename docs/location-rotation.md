終わったら `[x]` に変えて実施日とレポートのパスを書く。

エリアの追加・並べ替えは自由。**先頭に入れたエリアが次回の対象**になる。

## 各回で必ず押さえる項目

エリアが変わっても、比較できるよう**同じ切り口**で埋める。
取れなかった項目は削らず「未確認」として残す。

1. **人口動態** — 総人口の推移と将来推計、世帯数、年齢構成（高齢化率）
2. **競合** — 歯科診療所数、人口10万対の密度、駅別の集積度
3. **診療圏** — 500m / 1km 圏の人口、線路・河川・幹線道路による分断
4. **賃料** — 駅前 / 住宅地 / ロードサイドの坪単価、保証金の月数、居抜きの有無
5. **将来要因** — 再開発、新駅、大規模住宅の供給、乗降客数の推移
6. **エリア固有の論点** — 屋外広告物条例、医療モールの有無、自治体の助成

## 横断比較

3〜4エリア溜まった時点で、上記1〜5を並べた比較表を
`reports/location/_comparison.md` に作る。単発のレポートより、
**エリア間の差**のほうが判断材料になるため。

## 注意

- **「このエリアが有利」と順位づけしない。** 条件と前提を並べるところまで。
  最終的な優劣は、相談者の資金規模・診療方針・生活圏と突き合わせて決まる
- 賃料・人口データは**調査時点**を必ず記載する
- 実行環境の制約で一次情報のページを直接開けない場合があるため、
  数値は原則「未確認・二次情報」として扱う（`docs/runbook.md` 参照）
